Datasets API
============

For dataset BibTeX entries and preprocessing references, see
:ref:`cite-datasets`. Cite additional metadata sources when their features
contribute to your experiment.

Steam checkpoints
-----------------

Steam uses raw McAuley reviews and game metadata with original product IDs.
Every review is an implicit interaction, including negative reviews. Game
metadata contains titles, genres, tags, developers, publishers, release dates,
prices, specifications, and URLs where supplied by the source. Descriptions
are not supplied by this release. Missing metadata does not remove interactions
unless a positive ``min_entity_text_words`` is explicitly requested.

.. code-block:: python

   import compresso_recsys as cr

   checkpoint = cr.build_recsys_checkpoint(
       dataset="steam",
       split_mode="leave_last_out",
       checkpoint_path="artifacts/steam/llo.zip",
   )

   # Cold-start validation/test games are held out of training.
   cold_checkpoint = cr.build_recsys_checkpoint(
       dataset="steam",
       split_mode="item_split",
       checkpoint_path="artifacts/steam/cold.zip",
       min_entity_text_words=1,  # Require usable item text for this experiment.
   )

The equivalent CLI is:

.. code-block:: console

   compresso-recsys-build-checkpoint --dataset steam --split_mode leave_last_out --checkpoint_path artifacts/steam/llo.zip

Use ``split_mode="temporal"`` and ``temporal_period_hours=30*24`` for 30-day
target windows. The existing temporal protocol requires data spanning more
than three target windows. Steam and Netflix dates have day precision; LLO
ties retain source order. Compresso's LLO protocol has train/validation/test
targets and is not an exact reproduction of BERT4Rec's evaluation protocol.

The first Steam download is approximately 1.2 GB plus a small metadata archive.
Parsing retains only canonical interaction columns, in 100,000-row batches,
and writes a reusable Parquet cache. The final DataFrames and checkpoint
construction still require memory proportional to the dataset. No pretrained
text embeddings are generated by the dataset loader.

Additional datasets and defaults
----------------------------------

.. list-table:: Checkpoint builder defaults for new adapters
   :header-rows: 1

   * - Name / class
     - Feedback and support
     - Item metadata / time
   * - ``steam`` / ``Steam``
     - Every review; 5 events per user, 1 per item
     - Game fields; day-precision review dates
   * - ``netflix`` / ``NetflixPrize``
     - Ratings >= 4; 5 per user, 1 per item
     - Movie title/year; day-precision rating dates
   * - ``taste-profile`` / ``TasteProfile``
     - Play counts binarized; 20 per user, 200 per item
     - IDs only; no timestamps
   * - ``gowalla`` / ``Gowalla``
     - Check-ins; 10 per user, 10 per item
     - Latitude/longitude; timestamped events

Raw adapters preserve ratings/counts and repeated events. The builder collapses
duplicate user-item pairs for user/item CF splits; ordered splits retain events.
The new adapters default to zero minimum text words. Existing adapters continue
to use their previous 30-word builder default. Support and split arguments are
overridable. Temporal splits use the existing phase-specific support filtering.
Taste Profile rejects LLO/temporal splits because play counts have no timestamps.
Its item catalog is suitable for CF, but meaningful item cold-start features
require a separate metadata source. Gowalla supplies coordinates, not item text.

Netflix/MSD defaults are based on
`Mult-VAE <https://arxiv.org/abs/1802.05814>`_. Gowalla's CF support defaults
follow `NGCF <https://arxiv.org/abs/1905.08108>`_; this adapter uses raw SNAP
check-ins, not the authors' remapped LightGCN train/test files. Steam's feedback
convention follows `BERT4Rec <https://arxiv.org/abs/1904.06690>`_. These are
practical defaults, not claims of bit-identical paper reproduction: the builder
uses its own split protocols, random generator, and iterative support filtering.

Sources and local caches
------------------------

* `Steam <https://cseweb.ucsd.edu/~jmcauley/datasets.html#steam_data>`_:
  ``data/steam/steam_reviews.json.gz`` and ``steam_games.json.gz``.
  Retain the upstream citation/usage information.
* `Netflix Prize archive <https://archive.org/details/nf_prize_dataset.tar>`_:
  ``data/netflix/nf_prize_dataset.tar.gz``. Original Netflix usage terms apply;
  Compresso does not redistribute the dataset. Nested ``training_set.tar`` and
  archives containing per-movie files directly are supported.
* `MSD Taste Profile <http://millionsongdataset.com/tasteprofile/>`_:
  ``data/taste-profile/train_triplets.txt.zip``. The original archive is served
  over HTTP; the old S3 mirror is unavailable. MSD/Echo Nest usage terms apply.
  Full MSD metadata and mismatch lists are not downloaded by this adapter.
* `Gowalla <https://snap.stanford.edu/data/loc-gowalla.html>`_:
  ``data/gowalla/loc-gowalla_totalCheckins.txt.gz``. Cite the SNAP source paper;
  the social graph is not downloaded.

An existing archive in the documented location is reused without network access.
Canonical cache files are regenerated when the source size or modification time
changes. Interrupted downloads are not treated as complete archives. No new
optional dependencies, accounts, or Kaggle credentials are required.
